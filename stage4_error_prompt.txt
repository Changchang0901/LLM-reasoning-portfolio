### Error Categories
Every error MUST be classified into exactly one of these four categories:
**`factual`** — The model states or uses a known result, identity, formula, constant, or earlier derivation result that is **wrong on its face**. This includes:
- Misquoted standard identities or Feynman rules (e.g., wrong Casimir, wrong trace identity)
- Misremembered constants or numerical values
- Incorrectly recalling the problem statement
- Incorrectly recalling a result derived in an earlier step of its own reasoning
A factual error can be identified by checking the stated fact against a textbook or against the model's own earlier steps — no further context about the derivation logic is needed.
**`mathematical`** — The model chose the **correct approach** but made an error **during the computation**. Examples:
- Dropping a factor, wrong sign during integration or differentiation
- Incorrect algebraic simplification or rearrangement
- Arithmetic mistakes
- Missing or extra terms when expanding an expression
**Test:** If the model had executed the same mathematical operation correctly, the error would disappear.
**`logical`** — The model chose the **wrong approach, formula, or reasoning strategy** — even if the subsequent algebra is executed correctly. Examples:
- Using the massless propagator when the massive one is needed
- Applying an identity or theorem outside its domain of validity
- Setting up the wrong integral or equation for the quantity being computed
- Invalid deductions, non sequiturs, circular reasoning, unjustified assumptions
- Skipping a necessary step and asserting a conclusion without derivation
**Test:** Even if the model had done the algebra perfectly, it would still get the wrong answer because it is computing the wrong thing.
**`executional`** — A bug introduced **only in the code implementation** that is not present in the analytical reasoning. Examples:
- Wrong variable name or type in code
- Syntax-level mistakes or off-by-one indexing
- Incorrect symbolic-to-numeric translation that does not reflect the analytical steps
- Using the wrong function or library call
### Error Counting Rules
- **Do NOT double-count propagated errors.** If an analytical error (factual, mathematical, or logical) is then faithfully translated into code, do NOT flag the code version separately as executional. Only flag executional errors for bugs that introduce *new* mistakes not present in the analytical reasoning.
- **Flag each independent error once**, at the step where it first occurs. If a single error propagates through later steps, do not re-flag it at each subsequent step.
### Severity
- **`major`**: This error contributed to the wrong final answer. If it had been corrected, the final answer would change.
- **`minor`**: This error is present in the reasoning but did not affect the final answer (e.g., a sign error in an intermediate expression that was corrected later, or an error in an unused branch of reasoning).
### Primary Error Category
The `"primary_error_category"` is the category of the single most important error — the earliest major error that, if corrected, would have the largest impact on the final answer. It MUST equal the `"error_category"` of one of your major errors.
